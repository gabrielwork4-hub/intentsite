Core Web Vitals: O que São e Como Melhorar sua Pontuação

O Google usa Core Web Vitals como fator de ranqueamento desde 2021 — e em 2026, eles se tornaram ainda mais relevantes com a expansão do índice mobile-first. Sites lentos ou instáveis perdem posições para concorrentes mais rápidos, independentemente da qualidade do conteúdo.

O que são Core Web Vitals?

Core Web Vitals são 3 métricas de experiência do usuário definidas pelo Google como sinais de qualidade de página: LCP (Largest Contentful Paint) mede o tempo até o maior elemento visual carregar, INP (Interaction to Next Paint) mede a velocidade de resposta a cliques e interações, e CLS (Cumulative Layout Shift) mede a estabilidade visual — quanto a página 'pula' enquanto carrega.

Metas e Como Medir

Metas aprovadas pelo Google: LCP abaixo de 2,5s (bom) / 2,5–4s (precisa melhorar) / acima de 4s (ruim). INP abaixo de 200ms (bom) / 200–500ms (precisa melhorar) / acima de 500ms (ruim). CLS abaixo de 0,1 (bom) / 0,1–0,25 (precisa melhorar) / acima de 0,25 (ruim).

Meça com: PageSpeed Insights (pagespeed.web.dev), Google Search Console → Experiência → Core Web Vitals e a extensão Chrome 'Web Vitals'.

Como Melhorar o LCP

O LCP é o mais impactante para SEO.

Causas comuns de LCP ruim e soluções: (1) imagem hero sem otimização → comprima para WebP, adicione atributo loading='eager', use preload para a imagem principal; (2) servidor lento → use CDN, ative cache de página; (3) CSS que bloqueia renderização → inline o CSS crítico, adie o CSS não crítico; (4) fontes externas lentas → use preconnect para Google Fonts ou faça self-host das fontes.

Como Melhorar o CLS

CLS alto causa a frustração de clicar em um botão que se move no momento do clique.

Causas: imagens sem atributos de tamanho definidos (width e height), anúncios ou iframes que carregam e empurram o conteúdo, fontes com FOUT (Flash of Unstyled Text).

Solução: sempre defina width e height em imagens, reserve espaço para elementos que carregam dinamicamente, use font-display: optional ou swap para fontes.

Como Melhorar o INP

INP mede responsividade. Causas de INP ruim: JavaScript pesado bloqueando a thread principal, event listeners mal otimizados, re-renders desnecessários em frameworks JavaScript. Soluções: reduza o JavaScript não utilizado, use code splitting, adie scripts não críticos com async/defer, e minimize o uso de third-party scripts (chatbots, widgets de redes sociais) que bloqueiam a interação.

Perguntas Frequentes sobre Core Web Vitals

Core Web Vitals afetam o ranqueamento?

Sim, são um fator de ranqueamento confirmado pelo Google desde 2021. São usados como 'desempate' entre páginas de qualidade similar — dois sites com conteúdo de mesma qualidade, o mais rápido rankeia melhor. Em 2026, com a expansão do mobile-first indexing, o impacto dos Core Web Vitals no ranqueamento mobile é ainda maior.

Como verificar Core Web Vitals do meu site?

Use o PageSpeed Insights (pagespeed.web.dev) para verificar página por página. Para visão completa do site, acesse o Google Search Console → Experiência → Core Web Vitals — mostra quais URLs têm problemas e quantas páginas estão em cada categoria (bom, precisa melhorar, ruim).

Core Web Vitals ruins podem me fazer perder posição?

Sim, mas o impacto varia. Sites com Core Web Vitals muito ruins (LCP acima de 4s, CLS acima de 0,25) podem perder posições para concorrentes com métricas boas. O impacto é proporcional à competitividade do nicho — em nichos com poucos sites concorrentes, o conteúdo ainda supera os CWV. Em nichos competitivos, qualquer desvantagem técnica pode ser decisiva.

WordPress lento: como melhorar Core Web Vitals?

Para WordPress: instale um plugin de cache (WP Rocket, LiteSpeed Cache ou W3 Total Cache), use um CDN (Cloudflare é gratuito), instale um plugin de otimização de imagens (Smush, ShortPixel), defina tamanhos de imagem no código, e desative plugins não utilizados. O tema também impacta muito — temas pesados como Avada ou Divi têm LCP estruturalmente maior que temas leves como GeneratePress ou Astra.

Qual a diferença entre FID e INP?

FID (First Input Delay) foi o predecessor do INP e media apenas o primeiro clique do usuário. INP (Interaction to Next Paint), que substituiu o FID em março de 2024, mede a latência de TODAS as interações durante a visita — não só a primeira. O INP é uma medida mais completa e mais rigorosa de responsividade.
