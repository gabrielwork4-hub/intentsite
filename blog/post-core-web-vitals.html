Core Web Vitals: O que São e Como Melhorar sua Pontuação

O Google usa Core Web Vitals como fator de ranqueamento desde 2021 — e em 2026, eles se tornaram ainda mais relevantes com a expansão do índice mobile-first. Sites lentos ou instáveis perdem posições para concorrentes mais rápidos, independentemente da qualidade do conteúdo, porque a performance técnica também é experiência do usuário.

O Que São os Core Web Vitals

Os Core Web Vitals são um conjunto de métricas que medem, na prática, como o usuário real sente o carregamento, a interatividade e a estabilidade visual de uma página. Não se trata de uma nota abstrata de laboratório, e sim da experiência percebida por quem acessa o seu site no dia a dia, muitas vezes em conexões móveis e dispositivos modestos. Hoje elas são três: LCP (Largest Contentful Paint), INP (Interaction to Next Paint) e CLS (Cumulative Layout Shift).

Uma mudança importante aconteceu em março de 2024, quando o INP substituiu oficialmente o antigo FID (First Input Delay) como métrica de responsividade. O INP é mais rigoroso: em vez de medir apenas a primeira interação, ele avalia a latência de praticamente todas as interações ao longo da visita. Quem otimizou o site apenas para o FID precisa revisar essa frente.

Vale distinguir dados de laboratório de dados de campo. Ferramentas como o Lighthouse simulam o carregamento em ambiente controlado, enquanto o relatório CrUX (Chrome User Experience Report) e o Search Console mostram a experiência real dos usuários. É o dado de campo que efetivamente conta para ranqueamento.

LCP — Largest Contentful Paint

O LCP mede o tempo até o maior elemento visível da página ser renderizado — geralmente uma imagem de destaque, um banner ou um bloco grande de texto. A meta é simples: um LCP de até 2,5 segundos é considerado "bom".

As causas mais comuns de um LCP ruim são imagens pesadas, servidores lentos, recursos que bloqueiam a renderização e fontes que demoram a carregar. Para melhorar, comece otimizando as imagens: use formatos modernos como WebP ou AVIF, defina dimensões explícitas e aplique carregamento prioritário no elemento principal (por exemplo, fetchpriority="high").

Outras ações de alto impacto incluem adotar uma CDN para reduzir a distância até o servidor, habilitar cache eficiente, e usar preload para a imagem ou fonte crítica. Reduzir o tempo de resposta do servidor (TTFB) também costuma destravar ganhos imediatos no LCP.

INP — Interaction to Next Paint

O INP mede a responsividade: quanto tempo a página leva para reagir visualmente quando o usuário clica, toca ou digita. A meta de um bom INP é de até 200 milissegundos.

O grande vilão aqui costuma ser o JavaScript. Scripts pesados que travam a thread principal fazem o navegador "engasgar" ao responder às interações. Para melhorar, divida o JavaScript em pedaços menores (code splitting), adie ou carregue de forma assíncrona o que não é essencial, e remova bibliotecas que você não usa de fato.

Tarefas longas (long tasks) devem ser quebradas para liberar a thread principal com frequência. Um exemplo prático: em vez de processar uma lista enorme de uma só vez ao clicar em um botão, processe em blocos, devolvendo o controle ao navegador entre eles. Tags de terceiros — chats, pixels e widgets de analytics — também merecem auditoria, pois costumam ser as maiores responsáveis por interações lentas.

CLS — Cumulative Layout Shift

O CLS mede a estabilidade visual: aquele incômodo de a página "pular" enquanto carrega, fazendo você clicar no lugar errado. A meta de um bom CLS é de até 0,1.

As causas clássicas são imagens e anúncios sem dimensões reservadas, conteúdo injetado dinamicamente acima do que já está visível, e fontes que mudam o layout ao carregar. A solução principal é reservar espaço: sempre defina largura e altura (ou aspect-ratio) para imagens, vídeos e iframes, de modo que o navegador já saiba o espaço que cada elemento vai ocupar.

Para banners e blocos dinâmicos, reserve previamente a área que eles vão preencher. No caso das fontes, use estratégias como font-display: optional ou pré-carregamento para evitar saltos quando a fonte personalizada finalmente aparece.

Como Medir e Monitorar

Otimizar sem medir é apostar no escuro. O Google Search Console tem um relatório dedicado de Core Web Vitals com dados reais de campo, agrupando URLs por status (bom, precisa melhorar, ruim). O PageSpeed Insights combina dados de laboratório e de campo para uma única URL, e o Lighthouse (no Chrome DevTools) é ideal para testes durante o desenvolvimento.

A recomendação é tratar performance como um processo contínuo: meça antes de qualquer mudança, faça uma melhoria por vez, e valide o impacto com dados de campo — que levam alguns dias para refletir as alterações. Monitorar continuamente evita que regressões silenciosas (um novo script, um banner novo) destruam o que você conquistou.

Perguntas Frequentes sobre Core Web Vitals

Core Web Vitals afetam o ranqueamento?

Sim, são um fator de ranqueamento confirmado pelo Google desde 2021. São usados como 'desempate' entre páginas de qualidade similar — dois sites com conteúdo de mesma qualidade, o mais rápido rankeia melhor. Em 2026, com a expansão do mobile-first indexing, o impacto dos Core Web Vitals no ranqueamento mobile é ainda maior.

Como verificar Core Web Vitals do meu site?

Use o PageSpeed Insights (pagespeed.web.dev) para verificar página por página. Para visão completa do site, acesse o Google Search Console → Experiência → Core Web Vitals — mostra quais URLs têm problemas e quantas páginas estão em cada categoria (bom, precisa melhorar, ruim).

Core Web Vitals ruins podem me fazer perder posição?

Sim, mas o impacto varia. Sites com Core Web Vitals muito ruins (LCP acima de 4s, CLS acima de 0,25) podem perder posições para concorrentes com métricas boas. O impacto é proporcional à competitividade do nicho — em nichos com poucos sites concorrentes, o conteúdo ainda supera os CWV. Em nichos competitivos, qualquer desvantagem técnica pode ser decisiva.

WordPress lento: como melhorar Core Web Vitals?

Para WordPress: instale um plugin de cache (WP Rocket, LiteSpeed Cache ou W3 Total Cache), use um CDN (Cloudflare é gratuito), instale um plugin de otimização de imagens (Smush, ShortPixel), defina tamanhos de imagem no código, e desative plugins não utilizados. O tema também impacta muito — temas pesados como Avada ou Divi têm LCP estruturalmente maior que temas leves como GeneratePress ou Astra.

Qual a diferença entre FID e INP?

FID (First Input Delay) foi o predecessor do INP e media apenas o primeiro clique do usuário. INP (Interaction to Next Paint), que substituiu o FID em março de 2024, mede a latência de TODAS as interações durante a visita — não só a primeira. O INP é uma medida mais completa e mais rigorosa de responsividade.
